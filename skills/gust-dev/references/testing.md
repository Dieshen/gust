# Testing the Gust compiler

## The invariant

Most codegen tests assert on emitted strings. **Strings do not tell you whether the output compiles.** Three backends — wasm, no_std, and ffi — had never had their output fed to a compiler, and two of the three did not compile when someone finally tried it. `wasm` and `nostd` were deleted in 1.0 rather than frozen into the stability promise.

So the hierarchy of test value, strongest first:

1. **Compile the output with the real toolchain** (`codegen_backends.rs`) — the only test that catches "emits plausible-looking code that `rustc` rejects".
2. **Assert on semantic structure** — that a trait method exists with the right shape.
3. **Assert on substrings** — cheap, brittle, and blind to whether the result is valid code. Fine as a supplement, insufficient alone.

## Test map

All in `gust-lang/tests/` unless noted.

| File | Responsibility |
|---|---|
| `codegen_backends.rs` | **Compiles fixtures with every backend's real toolchain.** Add a fixture here for any new language form. |
| `generated_code_compilation.rs` | Compilation checks for generated Rust |
| `diagnostics_validation.rs` | The validator's error and warning surface — the largest suite |
| `language_semantics.rs` | End-to-end language behavior |
| `codegen_edge_cases.rs` | Awkward shapes that previously broke a backend |
| `formatter_roundtrip.rs` | `gust fmt` must round-trip — a new form silently destroyed by the formatter is caught here |
| `schema_generation.rs` | JSON Schema backend |
| `action_keyword.rs`, `action_handler_safety.rs`, `action_codegen_metadata.rs` | The `action` keyword: parsing, the one-action-per-path and last-side-effect rules, and emitted metadata |
| `go_codegen_concurrency.rs`, `rust_codegen_concurrency.rs` | Channels, `send`, `spawn`, supervision per backend |
| `target_backends.rs` | Backend selection and dispatch |
| `generics_support.rs` | Generic machines and bounds |
| `import_resolution.rs` | `use` declarations and stdlib imports |
| `tracing_codegen.rs` | `--tracing` instrumentation |
| `parser_property_tests.rs` | Property tests over the parser |
| `docs_snippets.rs` | Every ```` ```gust ```` block in `docs/src/` parses and generates |
| `cli_integration.rs` (in `gust-cli/tests/`) | CLI end-to-end: flags, exit codes, file outputs |

Other crates with their own suites: `gust-lsp`, `gust-mcp`, `gust-runtime`, `gust-stdlib`, `gust-template`, and `docs/tests`.

## Adding a codegen_backends fixture

Fixtures are `&'static str` constants of `.gu` source, collected into a table. Each is generated by every backend and handed to that backend's compiler. The existing `RICH` fixture deliberately covers user types, a fieldless enum, state fields, sync and async effects, ctx rewriting, and branching — the shapes that broke in practice:

```rust
const RICH: &str = r#"
enum Tier { Fast, Slow }

type Config { service_name: String, retries: i64, tier: Tier }

machine DeployPipeline {
    state Idle(config: Config)
    state Running(config: Config, attempt: i64)
    state Done(message: String)
    state Failed(reason: String)

    transition start: Idle -> Running
    transition finish: Running -> Done | Failed

    async effect deploy(name: String) -> String
    effect log(msg: String) -> bool

    async on start(ctx) {
        let result = perform deploy(ctx.config.service_name);
        perform log(result);
        goto Running(ctx.config, 1);
    }
    ...
}
"#;
```

When adding a fixture, prefer extending an existing one over adding a near-duplicate — every fixture costs a full toolchain invocation per backend, and the suite is already the slowest thing in the workspace. Add a new fixture when the shape is genuinely distinct (a new declaration form), extend `RICH` when it's a variation.

Because each fixture spawns real `cargo` and `go` builds, this suite dominates runtime. That's the tradeoff for it being the only suite that catches real breakage.

## Running

```bash
cargo test --workspace --all-targets --all-features
cargo test -p gust-lang
cargo test -p gust-lang --test codegen_backends
cargo test -p gust-lang --test diagnostics_validation
cargo test -p gust-lang -- some_test_name
```

**Examples are excluded from the workspace**, so they need explicit manifests and are easy to forget:

```bash
cargo test --manifest-path examples/event_processor/Cargo.toml
cargo test --manifest-path examples/microservice/Cargo.toml
cargo test --manifest-path examples/workflow_engine/Cargo.toml
```

A codegen change that breaks an example passes `cargo test --workspace` and fails CI. Run these before pushing anything that touches codegen.

Go smoke test:

```bash
gust build examples/order_processor.gu --target go --output _tmp --package smoke
cd _tmp && go mod init smoke && go vet ./...
```

## Mutation testing

The config **must** be at `.cargo/mutants.toml`. A `mutants.toml` at the repo root is silently ignored — no warning, it simply has no effect.

```bash
cargo mutants --file gust-lang/src/validator.rs    # logic-heavy, best value per minute
cargo mutants --shard 1/8                          # sample the workspace
```

Reading the report is the actual skill. Every survivor is one of two things:

- **A real coverage gap** — write a test that kills it.
- **An equivalent mutant** — it cannot change observable behavior. Document why and accept it.

Chasing a 100% score by suppressing the second kind is theatre. The value of the exercise is being forced to articulate why each survivor is safe.

The config excludes indent bookkeeping (`self.indent += 1`) in `codegen.rs` and `codegen_go.rs`: 368 of the workspace's 1734 mutants — 21% — were these, and all are equivalent, because flipping the operator only changes whitespace in generated code that no test asserts on and no consumer toolchain cares about. Triaging twenty whitespace survivors per real finding is how a team abandons mutation testing.

The exclusion is deliberately scoped to those two files rather than applied to the operator globally, so genuine compound assignments stay in scope: brace-depth counters in `format.rs`, scanner cursors in `parser.rs`, and the incoming-transition counter in `validator.rs` that drives unreachable-state detection.

Keep `-j` modest. Parallel mutants each spawning their own toolchain contend badly.

## What to write for a new feature

- A parse test (valid form produces the expected AST).
- A negative parse test (the form's near-miss is rejected).
- A validator test if there's a semantic rule.
- A `codegen_backends.rs` fixture — non-negotiable, this is what proves the output compiles.
- A `formatter_roundtrip.rs` case, or `gust fmt` may silently eat the new syntax.
